## 1. 托盘：左键打开窗口，右键打开菜单

### 1.1 为什么换掉 systray

原实现用 `github.com/getlantern/systray` v1.2.2。它的 Windows 窗口过程把左键和
右键写在同一个分支里：

```go
case WM_RBUTTONUP, WM_LBUTTONUP:
    t.showMenu()
```

也就是说左键必然弹出菜单，"左键打开主界面"在这个库上无法实现。Clash Verge Rev
的模型是左键=窗口、右键=原生菜单，因此新增 `native/windows/internal/tray`
自己实现窗口过程，并移除了 systray 依赖（`go.mod` 里 `getlantern/systray` 与
仅供其使用的 `getlantern/golog` 一并删除；残留的 `// indirect` 条目等有网络时
用 `go mod tidy` 清理即可，不影响构建）。

### 1.1.1 图标配色：内核在跑 ≠ 已接管流量

首版把 `CoreState == running` 也算进绿色 `active`。界面启动会拉起内核，于是**图标
一开就变绿**，而系统代理还是关的、机器上的流量也没走这个应用——图标在替用户宣布
一件没发生的事。已改为只有真正改了路由的两个开关才换色：

| 状态 | 底色 | 判定 |
| --- | --- | --- |
| `idle` | `#6B4FBB` 原色紫 | 系统代理关闭且未启用 TUN |
| `active` | `#3E9A3E` 绿 | **系统代理已开启** |
| `tun` | `#0F6CBD` 蓝 | TUN 已启用 |

`trayTooltip` 与颜色同步改写，两者回答同一个问题，不允许互相矛盾：紫配
"内核运行中，系统代理未开启"，绿配"代理运行中：{节点}"，开关开着但内核挂了则保留
开关对应的颜色并在提示里点名异常。每次变体切换都写一行
`托盘图标切换为 active（代理运行中）`，这样托盘出了问题是能从日志查的。

真实运行验证（`.tmp/tray-idle`，无内核）：启动 → `idle`；`systemProxy.set
enabled=true` → `active（代理运行中）`；再关掉 → 回到 `idle（代理已停止）`。

### 1.2 左键

**开/关主界面**（toggle），判定依据是"窗口是不是当前前台窗口"：

- 窗口不在 → 启动 `clash-halo.exe`。启动前轮询 6×250ms 等窗口出现，避免"正在
  启动"时再开第二个实例。
- 窗口存在但不在前台（被别的窗口盖住、最小化）→
  `ShowWindow(SW_RESTORE)` + 置顶/取消置顶 + `SetForegroundWindow`。置顶再取消
  置顶是突破 Windows 前台锁的标准做法，Verge 用的也是这一招。
- 窗口已在前台 → `ShowWindow(SW_HIDE)` 收起。

关于与 Verge 的差异：Verge 的左键只做"显示"，其维护者在源码分析里把这一点列为
缺陷（点已经在前台的窗口图标毫无反应）。这里做 toggle，但**隐藏用的是 SW_HIDE
而不是关窗**：界面进程继续存活，托盘能立刻拉回来；而窗口的 × 按钮走的是另一条
路径，会真正退出 UI 进程（后台继续跑代理，见 `方案.md` §4.1）。

### 1.3 右键菜单

原生 `TrackPopupMenuEx` 菜单，**每次右键都用实时状态重建**，不维护菜单项句柄，
因此勾选态不可能过期。结构照抄 Verge 的分区：

```text
打开主界面
─────────────
出站模式（规则） ▸  规则 / 全局 / 直连      ← 单选，标题带当前模式
─────────────
节点 ▸   {节点名 · 分组}                  ← 单选，当前节点打勾
─────────────
☑ 系统代理
☑ TUN 模式
─────────────
打开目录 ▸  数据目录 / 日志目录 / 配置目录
更多 ▸     重启代理内核 / 重新打开界面 / 版本
─────────────
退出（断开代理）
```

菜单项的能力缺失时置灰而不是点了再报错（系统代理不支持、TUN 不可用时）。

### 1.4 托盘切换节点为什么要绕一圈

托盘能列出节点，但**不能自己生成配置**：节点 → sing-box 文档的生成器在 Dart
（`packages/config`），Go 侧再写一份就是第二个事实来源。所以：

1. 界面把精简节点表（id、名称、分组，最多 60 条）通过新增的 `tray.publish`
   动作发布给后台；数据库仍然是唯一权威。
2. 托盘点节点 → 后台写入 `tray-request.json` 并广播 `tray.command` 事件。
3. 界面收到事件立即处理；界面没开时，下次启动读取该文件（只接受 2 分钟内的
   请求，避免陈旧文件在无关启动时偷偷切节点）。

这样托盘在不打开窗口时也能完成最常见的"换个节点"操作，而不需要后台理解业务。

### 1.5 未做的部分

- 托盘没有"开机自启"项：Verge 也没有，自启在设置页。
- 托盘也没有"启动时恢复内核"项：那是设置页的一个开关，默认开。它在同一张卡片里紧挨
  「开机自动启动」，因为两者是同一个意图的两种粒度（要不要后台常驻 / 常驻后要不要
  把内核也拉起来）。
- TUN 从托盘切换会直接触发 UAC，与界面一致；失败时打开窗口展示原因（托盘没有
  地方显示错误）。

## 2. 节点页

参考 v2rayN 的 ProfilesView（WPF/Avalonia 双实现 + 共享 VM），取其中真正影响
易用性的部分：

| 改动 | 之前 | 现在 |
| --- | --- | --- |
| 订阅分组 | 无，全部节点一张平表 | 表格上方 chips：全部 / 本地 / 每个订阅（带计数），点击切换 |
| 选中方式 | 每行常驻复选框 | 点击 / Ctrl+点击 / Shift+范围；表头不再被复选框占位 |
| 当前节点 | 行底色 + 文字徽标 | 左侧 3px 强调条 + "使用中"徽标，与"选中"用不同视觉 |
| 列 | 名称/类型/地址/端口/延迟 | 增加 **传输 / TLS / 分组** 三列，八列全部可排序 |
| 延迟 | 只有数字 | 测速中的行显示"测试中"+ 转圈，结束才有数字；失败与未测区分 |
| 右键 | 5 项平铺 | 分组菜单：设为当前 / 测速 / 详情 / 重命名 / 移到分组 / 复制链接 / 删除 |
| 节点编辑 | 完全没有 | "节点详情"对话框：可改名称与分组，其余只读（地址/端口/凭据属于身份指纹） |
| 批量移动分组 | 完全没有 | 工具栏 + 右键菜单，支持移到本地或任一订阅 |
| 删除 | 直接删 | 先确认，再执行，仍可撤销 |
| 快捷键 | 无 | Enter 启用、Delete 删除、Ctrl+A 全选、Ctrl+C 复制链接、Ctrl+D 详情、Ctrl+F 搜索、Esc 停止测速、↑↓ 移动 |
| 状态条 | 无 | 底部：可见/总数、已选、当前节点、测速进度、常用快捷键 |
| 行尾操作列 | 常驻「启用」/「当前」64px 一列 | **去掉**：启用有页头按钮、右键菜单、Enter 三处入口；"当前"已由 3px 强调条 +「使用中」徽标表达 |

刻意**没有**照抄的：行号槽、四列流量统计（本项目没有按节点计费）、
"搜索必须回车才生效"（输入即时过滤更好用），以及行尾那一列"启用"——v2rayN
靠双击整行切换，这里靠页头按钮/右键/Enter，再排一列只是把同一个事实写第四遍，
还让表格窄了 64px。

## 3. 打通的功能（"界面有控件但不生效"）

第一轮修的是能从页面上直接看出来的断点；第二轮做了一次系统性审计（逐页对照
`方案.md` §9 与后台动作表），又找出并修掉了下面这些 —— 它们的共同点是"控件在，
点了也有反应，但结果不对或者根本到不了用户眼前"。

### 第一轮

1. **分流模式真正生效**：`proxy.setMode` 过去只改运行快照里的一个字段，内核仍在
   按旧配置路由。现在改模式会持久化到设置表并重新生成配置、重新应用。
2. **端口 / DNS / Fake-IP / 路由模式持久化**：这些值原本只存在分流页的
   `State` 里，离开页面即丢失。新增 `RoutingSettings`（`routing.*` 设置项），
   节点切换、总览页模式切换、分流页保存都走同一份设置。
3. **切节点不再重置分流配置**：`selectNode` 过去用 `RouteMode.rule` 和 7890 端口
   重新生成配置，覆盖用户设置；现在按已保存的 `RoutingSettings` 生成。
4. **订阅记录可管理**：新增编辑（名称/链接/更新间隔）、删除（连带节点，删除前
   提示节点数）、每行的定时更新开关（原来是长按，基本没人能发现）、失败原因
   可点开并直接重试。
5. **设置页可直接打开数据目录与日志目录**，与托盘菜单一致。

### 第二轮（审计发现）

6. **日志页此前没有任何真实内容**（P0）。三处问题叠在一起：宿主通过 `log.tail`
   返回的字段是 `{atMs, text}`，而 UI 用 `LogEntry.fromJson` 按 `{seq, atMs,
   level, source, message}` 解析，于是每行都是空文本；宿主从不广播
   `log.appended`；唯一的 tail 发生在连接成功那一刻，那时日志页还没挂载，事件
   直接丢了。现在 `logEntriesFromTail` 做形状映射，日志页在打开期间每 1.5s 拉一次
   tail 并按"上一行"做增量合并（不会重复追加），首次进入立刻有内容。
7. **总览"下一步"卡片与状态栏按钮点了没反应**（P1）。`去启动` / `去开启` 这两步
   指向的就是总览页本身，而 `_open` 对"已经在这一页"直接 return。`NextStep` 现在
   携带 `NextStepAction`，按钮执行的是那句话描述的动作（启动内核 / 开启系统代理），
   只有需要换页时才导航。
8. **系统代理端点与混合端口脱钩**（P1）。UI 里端点写死 `127.0.0.1:7890`，改了端口
   后开系统代理会把 Windows 指向没人监听的端口，而界面仍显示"已开启"。现在端点
   由 `RoutingSettings.mixedPort` 拼出；后台在每次应用配置后从新配置里读回
   `mixed` 入站端口并同步注册表（只改 Applied 值，保留用户的原始设置用于恢复）。
9. **导入粘贴内容会生成永远更新失败的订阅记录**（P1）。`_commit` 只为粘贴内容
   服务（URL 走 `_parse` 分支），却会创建 url 为空或截断到 200 字符的订阅记录；
   之后每次"更新"都报"订阅地址必须是 HTTP 或 HTTPS"，开了定时更新还会每分钟失败
   一次。现在粘贴内容只导入节点、不建订阅记录，名称输入框改为"仅订阅链接需要"。
10. **恢复备份读文件失败时毫无提示**（P1）。`readAsString` 在 try 之外，异常直接
    逃逸，用户点完"下一步"什么也没发生。整段流程已移入 try，统一走"恢复失败：$e"。
11. **订阅页"测速"可能静默失败**（P1）。`startSpeedTest` 的本地校验（无节点、节点
    无法生成配置）不经过 `_command`，所以既没有 snackbar 也没有错误条。现在
    catch 里给出消息、无节点时按钮禁用、测速中显示"测速中…"并在结束时复位。
12. **托盘"出站模式"只改字段不改配置**（P1）。点规则/全局/直连只把快照里的 mode
    改掉，路由规则还是旧的 —— 菜单显示"全局"，流量仍按规则走。现在与切节点同一
    套路：写 `tray-request.json` + 广播，由 UI 重新生成并应用；有窗口时静默处理，
    没窗口时才打开窗口（不能让菜单显示一个没生效的模式）。
13. **托盘切节点会强开窗口**（体验）。有窗口时直接应用，不再弹窗；只有没有窗口时
    才启动界面，因为请求必须由一个进程执行。
14. **删除订阅的承诺与实际不符**（P2）。确认框写"删除其 N 个节点"，仓储实际只是
    删记录、节点变成无主行（不出现在任何分组 chips 里）。现在给出两个明确选项：
    "只删订阅"（节点移到本地）或"删除订阅和节点"。
15. **导入/删除节点后托盘目录不刷新**（P2）。`saveImport` / `deleteNodes` 只
    bump 本地目录版本，没有重新发布给后台，托盘菜单会停在旧列表。
16. **托盘"更多 → 重新打开界面"是与"打开主界面"同义的重复项**（P2）。它的名字
    承诺重启，实际只是把窗口提到前面，已移除。

配套的小改动：`ProxyNode.movedToGroup()` 取代散落在各处的"手工重建节点"，因为
`copyWith(profileId: null)` 的含义是"保持原值"，无法表达"移回本地"。

新增回归测试（都是本轮发现的缺陷的"钉子"）：

- 节点页：真实导入 9 个节点后在 2360×1520（200% 缩放）与 1180×760 下渲染，
  断言表格/分组 chips/状态条存在且不溢出。这两项当场抓出两个真实缺陷（工具栏
  窄窗溢出 115px、端口列把 8443 截成 844）。
- 日志形状：`logEntriesFromTail` 用例覆盖宿主真实返回的 `{atMs, text}`、空文本
  与畸形输入，以及"将来若改为完整事件形状也要能解析"。
- 托盘菜单模型：首项/末项、模式子菜单标题与单选标记、节点子菜单的分组后缀与
  当前节点勾选、系统代理与 TUN 是勾选项、无目录时的占位项。
- 端口解析：`mixedInboundPort` 对 mixed/socks/http、缺端口、无入站、非法 JSON
  的六种输入。
- 节点分组：`movedToGroup(null)` 能真正清空 `profileId` 并把 source 改回 manual。
- 托盘图标配色：七种状态组合断言"只有内核在跑"仍是 `idle`，系统代理开才是
  `active`，TUN 优先；另有五个用例断言气泡文字与颜色不矛盾（紫不会说"代理运行中"，
  绿不会说"已停止"），并且"开关开着但内核挂了"必须在提示里点名异常。
- 节点页行尾列：断言 `启用` / `当前` 两个文字都不再出现在表格里，防止那一列被
  无意中加回来。

真实运行（本机 Windows 10，临时数据目录，不影响用户数据）：

- 启动 `halo-host.exe --dir .tmp\tray-smoke`，日志出现
  `[host] 托盘图标已应用（idle）`：新窗口过程 + `Shell_NotifyIcon` +
  ICO 加载链路可用。

- 通过真实命名管道发送 `tray.publish`（2 个节点），宿主返回 `{"count":2}`，
  说明界面→托盘的节点目录投影链路可用；随后启动真实界面连接该宿主，宿主日志出现
  `action=tray.publish`，确认界面在连接后会主动发布目录。
- 新增 `buildTrayMenu` 单元测试：断言首项是"打开主界面"、末项是"退出"、模式子菜单
  标题带当前模式且三项互斥、节点子菜单带分组后缀并标记当前节点、系统代理与 TUN
  是勾选项；无目录时保留"节点（打开界面后可切换）"占位项。
- 启动构建产物 `clash-halo.exe`（临时数据目录 + 8 个演示节点）并截图，确认节点页
  在真实 200% 缩放下版式、分组 chips 计数、列对齐与状态条均正确，且行尾已无
  「启用 / 当前」列（见 `images/ui-nodes-page.png`）。
