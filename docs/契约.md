# 通信契约

UI 与后台之间只有一条通道：Windows 命名管道上的 NDJSON。本文件是两侧实现
共同遵循的规格；任何一侧改动都必须同步另一侧，否则 UI 会连不上或读不懂。

## 1. 传输

| 项 | 值 |
| --- | --- |
| 管道名 | `\\.\pipe\clash-halo-host-v1-<hash>` |
| 编码 | UTF-8，每行一个 JSON 对象，以 `\n` 结尾 |
| 请求上限 | 1 MiB（`config.apply` 是最大合法请求） |
| 空闲超时 | 见 `internal/ipc` 常量；UI 最小化时连接保持 |

`<hash>` = 数据目录规范化后 UTF-8 字节的 FNV-1a 64 位值，小写十六进制、无
前导零填充。规范化：全部小写 → 反斜杠转斜杠 → 去掉空段 → 用 `/` 连接。

Dart 与 Go 各自实现，用固定向量测试对齐：

```text
haloPipeNameFor('D:/project/clash-halo') ==
  r'\\.\pipe\clash-halo-host-v1-3f9aa21224b50de8'
```

## 2. 帧格式

### 请求

```json
{"v":1,"id":"7","action":"config.apply","params":{"config":"…","startCore":true}}
```

- `v`：协议版本，当前恒为 `1`。不匹配返回 `version_mismatch`，不做兼容尝试。
- `id`：客户端生成的字符串，响应原样带回。
- `params`：动作相关，可为空对象。

### 响应

```json
{"v":1,"id":"7","ok":true,"result":{"configVersion":3},"stateVersion":3}
{"v":1,"id":"7","ok":false,"error":{"code":"config_invalid","message":"…","detail":"…"}}
```

`stateVersion` 只出现在响应中；客户端可据此判断是否需要重新拉取快照。

### 事件

```json
{"v":1,"event":"log.appended","seq":42,"data":{"level":"warn","message":"…"}}
```

`seq` 单调递增，客户端应丢弃比已见最大值小的帧。

## 3. 动作

| action | params | 说明 |
| --- | --- | --- |
| `snapshot.get` | — | 返回完整运行状态；重连后必须调用 |
| `host.status` | — | 轻量状态，含解析到的内核路径 |
| `host.shutdown` | — | 停止内核并退出后台 |
| `core.start` / `core.stop` / `core.restart` | — | 内核生命周期 |
| `config.apply` | `config`, `startCore` | 走完整流水线（校验→应用→健康检查→回滚） |
| `node.select` | `nodeId` | 切换当前节点并重写配置 |
| `proxy.setMode` | `mode` | `rule` / `global` / `direct` |
| `system.proxy.set` | `enabled` | 写系统代理并记录原值 |
| `tun.setEnabled` | `enabled`, `adapterName?`, `stack?`, `address?`, `mtu?`, `autoRoute?`, `strictRoute?` | 启用/停止 TUN；**首次启用**安装服务并阻塞至 UAC 答复，之后走服务，见 §5 |
| `tun.serviceStatus` | — | 报告服务是否安装、是否可达、当前由哪个后端接管 |
| `tun.serviceInstall` | — | 手动安装/修复服务（一次 UAC；首次启用会自动调用） |
| `tun.serviceUninstall` | — | 停止 TUN 后卸载服务（一次 UAC） |
| `speed.test.start` | `nodeIds` | 隔离测速，不经过当前代理 |
| `task.cancel` | `taskId` | 取消进行中的任务 |
| `log.tail` | `lines` | 取最近日志行 |
| `event.subscribe` | — | 订阅事件流 |

## 4. 错误码

两侧共用同一字符串集合（`HaloErrorCode` / `contract.Err*`）：

```text
unknown_action  bad_request  version_mismatch  unauthorized  forbidden
not_found  conflict  core_not_running  core_failed  config_invalid
config_apply_failed  unsupported_capability  tun_unavailable  elevation_denied
elevation_required  system_proxy_failed  task_not_found  task_canceled
already_running  busy  internal
```

规则：

- `elevation_required` 与 `elevation_denied` 必须区分：前者是“该动作需要管理员
  令牌”，后者是“用户拒绝了授权”。
- `unsupported_capability` 用于“内核不支持该协议参数”，不得混同为配置错误。
- `busy` 与 `conflict` 都表示当前状态不允许该操作；`busy` 可重试，`conflict`
  需要先改变状态。

## 5. TUN 的契约

TUN 已实现并在真实提权下验证（见 `docs/验证记录.md`）。它比其它动作多一层
“谁来做”的语义，因此契约也更严格：

- **安装时机**：安装包不注册 TUN 服务。第一次 `tun.setEnabled {enabled:true}`
  时，若服务尚不可用且随程序带有 `halo-tun-service.exe`，宿主通过 `runas`
  执行一次 `halo-tun-service.exe --install --app-dir … --data-dir …`，安装并
  启动服务，然后请服务启动内核。此后启用/关闭 TUN 只走命名管道，不再弹 UAC。
  应用更新导致随包内核摘要变化时，下一次启用会用同一流程更新服务一次。服务是
  唯一的 TUN 后端；服务二进制缺失即返回 `tun_unavailable`，没有第二条提权路径。
- **阻塞时间**：首次启用包含一次安装（最长等待 120 秒）与一次内核启动（最长 90
  秒）；界面命令超时为 240 秒。之后每次启用只等待内核启动。期间快照的
  `tunState` 为 `pending`，界面必须显示当前阶段（安装服务 / 启动内核），且不得
  允许重复触发。
- 成功返回 `{tunState, tunMessage, tunPid, tunAdapter, tunElevated}`。
  `tunAdapter` 是后端实际创建的适配器名（服务在注册冲突重试时可能改用带数字后缀
  的名字），`tunElevated` 是真实令牌检查结果；两者都取自后端，宿主不推断。
- 失败必须区分：
  - `elevation_denied`：用户拒绝首次安装的授权。这是正常结果，系统代理状态不受
    影响；安装被拒后不会再次弹出授权，避免一次操作两次提示；
  - `tun_unavailable`：服务或内核缺失、服务不可达、安装失败，或适配器未建立。
    `error.detail` 携带后端写回的真实原因（例如 `configure tun interface:
    Access is denied.`），界面必须展示它；
  - `config_invalid`：尚无可用配置，或 TUN 参数非法（stack/mtu/address/adapter）；
  - `internal`：其它。
- `tunSupported=false` 时快照的 `tunState` 为 `unsupported`，`tunMessage` 指明缺少
  哪个文件；界面必须禁用开关并显示该消息。可用条件是服务可达、已安装且数据目录
  匹配，或 `halo-tun-service.exe` 与内核同时存在。
- 启用前宿主要求已有可用配置。服务读取、校验并复制配置后才启动内核，因此不会为
  一个必然失败的配置消耗用户一次点击。
- 关闭 TUN 时：宿主发送 `stop`，服务优雅结束内核并删除路由/适配器；服务不可达
  时，服务进程持有的作业对象保证内核随服务结束。因此“已关闭”意味着适配器确实
  消失，而不只是宿主不再引用它。
- 服务生命周期（快照之外的约定）：服务设为自动启动，空闲时不运行内核；宿主退出
  后停止内核；服务重启/机器重启后不恢复内核，等宿主重新请求。宿主对服务不可达
  有 15 秒容忍期（覆盖 SCM 自动重启），超过才把状态置为失败。
- **测量隔离**：`speedtest.start` 的流量不得经过当前代理。代理模式下，临时测试
  内核使用自己的入站与配置，宿主拒绝把当前系统代理入口当作测试代理；TUN 模式下
  的绕过实现存在但**默认关闭**，启用前 TUN 开启时的测速会被拒绝而不是经过 TUN
  测量（见 `docs/tun-measurement-bypass.md`）。
- - `unverified` 是早期版本的遗留线值，仅为兼容旧快照保留，当前宿主不再产生。

TUN 与系统代理在实现上互斥：TUN 占用内核时普通内核会被停止；关闭 TUN 后，若系统
代理仍处于开启状态，或用户此前明确要求内核保持运行（`coreWanted`），宿主会恢复
普通内核。TUN 本身也是一条流量路径，因此“系统代理关闭”不等于“不需要内核”。

## 6. 重连语义

客户端断线重连后**不能**假设状态未变，必须重新 `snapshot.get`。后台不会补发
断开期间的事件；快照是唯一可靠的收敛点。

## 7. 兼容性

`v` 是唯一兼容开关。新增动作或错误码不需要升版本；改变帧结构、字段语义或
删除动作则必须升版本，并让旧客户端收到 `version_mismatch` 而不是解析错误。
