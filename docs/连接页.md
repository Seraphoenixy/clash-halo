# 连接页

日期：2026-11-04。

`方案.md` §9 列出的 Windows 页面里，连接页是最后一个没有实现的。本文记录它是
怎么接起来的、为什么这么接、以及验证到了什么程度。

## 1. 它回答什么问题

"现在有哪些连接正在走代理、各自走了哪条规则和哪个出口、是哪个程序发起的、开了
多久、各传了多少字节。" 排查"某个网站不工作"时，答案通常就在规则列和代理链列里：
一条本该直连的连接走了代理，或者一条本该走节点的连接落到了 DIRECT。

单个连接可以关掉，也可以一次关掉全部。关连接不影响代理本身，新的请求会重新建连。

## 2. 数据从哪来

```text
连接页(Flutter) --IPC--> halo-host --HTTP(回环)--> sing-box Clash API
```

UI 不直接访问 Clash API，原因有三条，都不是偏好问题：

1. 控制器监听在 `127.0.0.1:<clashApiPort>`，端口由**运行中的配置**决定，而那份
   配置由宿主写入并持有；UI 侧再猜一次端口就会在用户改端口后失效。
2. 宿主已经实现了"只允许回环地址"的校验，这个校验必须只有一个实现。
3. UI 不需要引入一套 HTTP 客户端去连本机服务，也就不会有人把 `HTTPS_PROXY`
   之类的环境变量带进来。

### 2.1 两个动作

| 动作 | 参数 | 返回 |
| --- | --- | --- |
| `connections.list` | 无 | `{connections, uploadTotal, downloadTotal, memory, controller}` |
| `connections.close` | `{id?}`，无 `id` 表示全部 | `{closed}` |

`controller` 字段是**数据来源**，界面上会显示出来。它存在的理由很实际：用户改了
Clash API 端口后，如果列表是空的，他需要能分辨"没有连接"和"根本没读到"。

### 2.2 只允许回环

地址不是从快照读的，而是每次从**正在运行的配置文件**里读
`experimental.clash_api.external_controller`——这样地址永远不会和内核实际监听
的端口不一致。读出来后再校验一次必须是回环地址：配置文件用户可以手工改，这是
"展示我的连接"变成"调用局域网里任意 HTTP 端点"之间唯一的一道门。

### 2.3 HTTP 客户端禁用代理

`http.Client` 显式设置 `Proxy: nil`。否则一旦用户打开系统代理，Go 的默认
Transport 可能把发往 `127.0.0.1:9090` 的请求也塞进代理，形成一个自己查自己的环。

## 3. 数据模型

Clash API 的连接对象是嵌套的：`host`/`process` 在 `metadata` 里，`rule`/`chains`
在外层。宿主在 `connections.go` 里把它拍平成 `Connection`，UI 只认拍平后的
`LiveConnection`。这样做的目的是把"第三方 API 的形状"关在一个结构体里——规范
要求 Clash API 只用于已核验的能力，耦合面越小越好核对。

`start` 保留原始字符串：sing-box 报的是纳秒精度
（`2026-11-04T08:37:09.8402524+08:00`），Dart 的 `DateTime.parse` 对超过 6 位的
小数在某些版本上会失败，所以模型里先截到微秒再解析。解析不出来时"时长"列显示
`—`，而不是抛异常——这一列每 1.5 秒重算一次。

## 4. 界面

- 顶部：搜索（主机 / 进程 / 规则 / 代理链）、匹配计数、"控制器 xxx"。
- 右侧动作：暂停刷新、关闭全部（二次确认）。
- 表格列：主机（目标 IP 与主机**不同时**才在第二行显示，否则同一串地址会出现两次）、
  进程、规则、代理链、上传、下载、时长。
- 关闭单个连接：**悬停时才出现**的红色 ×。每一行都常驻一个红叉会把诊断列表变成
  雷区。
- 空状态分三种：内核未运行（去总览启动）、没有活动连接（提示去访问网络）、
  筛选无匹配。
- 刷新：页面打开期间每 1.5 秒拉一次，可暂停；页面不在前台时 shell 会销毁它，
  计时器随之取消——不在看的页面不产生请求。

## 5. 验证

- Go 单测：`parseClashConnections` 用一段真实形状的抓包数据覆盖嵌套字段、按 IP
  建连时 `host` 回退到目标 IP、空列表是空切片（不是 null）、非法 JSON 报错；
  `isLoopbackAddress` 覆盖 `127.0.0.1:9090`、`[::1]:9090`、`localhost:9090`
  通过，`0.0.0.0`、`192.168.x.x`、`example.com`、缺端口被拒绝。
- 契约单测：`ConnectionsSnapshot.fromJson` 按宿主真实线格式解析；缺字段降级；
  纳秒时间戳可解析；时钟偏移导致的负时长被夹到 0；两个新动作常量与 `all` 集合一致。
- Widget 测试：注入固定数据的 loader，断言主机/进程/规则/代理链渲染、搜索过滤、
  空状态文案、1180×760（200% 缩放）下不溢出。
- **真实端到端**（`host_live_test.dart`，`--tags live`）：启动真实 `halo-host.exe`
  + 真实 `sing-box.exe`，应用一份带 Clash API 的配置，通过 mixed 入站发起一条
  连到一个"只接受不回应"的 TCP 服务的请求，然后 `connections.list` 轮询到它，
  断言 id/代理链/时间戳可解析、`controller` 是回环地址，最后用 `connections.close`
  关掉它。实测通过（8 项 live 测试全绿）。
- 另有一次手工冒烟：真实内核 + 真实挂起连接，宿主的 `connections.list` 返回
  `"chains":["direct"]`、`"rule":"final"`、`start` 为纳秒时间戳。
- 还有一次真实界面截图（本文顶部那张）：真实宿主 + 真实内核 + 三条挂起连接，
  界面侧栏「连接」可进入，表格、总计、控制器地址都正确。

## 6. 限制

- 需要配置里启用 Clash API（`experimental.clash_api`）。关掉之后页面会显示
  "无法查询连接列表"，而不是假装没有连接。原来在「分流与 DNS」页有一个开关，
  该页已删除；现在由生成器的默认值（开启）决定。
- 只有**活跃**连接，没有历史记录。sing-box 不提供连接历史，本项目也不落盘。
- "进程"列在 Windows 上取决于核心能否拿到发起进程；拿不到时显示 `—`，这不是
  界面缺陷。
- 关闭单个连接是立即执行的，没有撤销；连接本身是可重建的，所以没有做二次确认。
