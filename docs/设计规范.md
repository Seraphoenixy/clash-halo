# 界面设计规范(Fluent Design)

界面按 Microsoft Fluent Design(Fluent 2)实现。本文是取值的唯一来源:任何新
控件都应从这里的令牌取值,而不是写死颜色、圆角或字号。

> **截图不入库。** 本文中的界面图只是本地核对用的产物，克隆后不存在；
> 需要时现生成：`pwsh -NoProfile -File scripts/capture-window.ps1`。
> 原因与规则见 [agents/repo.md](agents/repo.md#界面截图不进仓库)。

## 1. 三层颜色

颜色分三层,每层职责单一。**只有中性层随深浅色切换**,强调层和语义层各自的
明暗值分别定义。

### 1.1 中性层(canvas / card / text)

| 令牌 | 浅色 | 深色 | 用途 |
| --- | --- | --- | --- |
| canvas | `#F3F3F3` | `#1F1F1F` | 窗口与导航栏底色 |
| card | `#FFFFFF` | `#2A2A2A` | 卡片、对话框 |
| cardHover | `#F7F7F7` | `#323232` | 悬停底色 |
| input | `#FFFFFF` | `#323232` | 输入框、选择器轨道 |
| pressed | `#EDEDED` | `#383838` | 按下底色 |
| border | `#E5E5E5` | `#3D3D3D` | 卡片描边、分隔线 |
| borderStrong | `#D6D6D6` | `#4A4A4A` | 输入框描边 |
| textPrimary | `#1B1B1B` | `#F2F2F2` | 标题与正文 |
| textSecondary | `#616161` | `#B4B4B4` | 说明文字、标签列 |
| textTertiary | `#8A8A8A` | `#8C8C8C` | 禁用、占位 |

获取方式:`HaloPalette.of(context)`,**不要**再写 `dark ? A : B` 三元式——
这正是此前浅色令牌漏进深色模式的原因。

### 1.2 强调层(品牌紫)

| 令牌 | 浅色 | 深色 |
| --- | --- | --- |
| accent | `#6B4FBB` | `#B4A0EA` |
| accentHover | `#7B5FCC` | — |
| accentPressed | `#5A3FA6` | — |
| accentSubtle | `#EFEBF9` | `#342A4E` |

深色下强调色必须提亮,否则 `#6B4FBB` 在 `#2A2A2A` 上对比度不足。
选中态用 `accentSubtle` 填充 + 3px 强调色竖条,不只靠填充色。

### 1.3 语义层

| 语义 | 浅色 | 深色 |
| --- | --- | --- |
| success | `#107C10` | `#54B054` |
| warning | `#9D5D00` | `#E0A33C` |
| danger | `#C42B1C` | `#FF7A70` |
| info | `#0F6CBD` | `#6CB4E8` |

辅助函数把这些颜色带到正确的一侧:

- `HaloColors.adapt(color, dark)` — 无 `BuildContext` 时使用(状态映射函数
  返回的仍是浅色令牌)。
- `haloAdapt(context, color)` — 有 `BuildContext` 时使用。
- `StatusChip` / `InfoRow` 内部已自动转换,直接传浅色令牌即可。

## 2. 几何

| 项 | 值 | 说明 |
| --- | --- | --- |
| 控件圆角 | 4 | 按钮、输入框、导航项 |
| 容器圆角 | 8 | 卡片、对话框、弹出菜单 |
| 控件高度 | 32 | 按钮、输入框、选择器、下拉 |
| 图标按钮 | 36 | 带 `visualDensity.compact` 时为 28 |
| 导航项高度 | 34 | 比控件略高,列表更透气 |
| 侧栏宽度 | 200 | |
| 页头 / 品牌栏 | 56 | 两者等高,分隔线与页头下边线对齐 |
| 内容内边距 | 16 | 页面与卡片之间 |
| 卡片内边距 | 12 | 标题下方 8(`blockGap`) |
| 卡片间距 | 12 | `HaloMetrics.cardGap`,卡片与卡片、横幅与网格、网格与整宽卡都用它 |
| 卡内块间距 | 8 | `blockGap`,同一张卡里两块内容之间 |
| 卡内行间距 | 4 / 2 | `lineGap` / `hairGap`,同一块里的两行、标签与其数字 |
| 状态徽章 | 20 | 字号 11 |
| 表格行 / 表头 | 38 / 34 | 节点、连接两张表 |
| 阴影 | `blur 4 / y 1 / alpha 8%`(深色 20%) | 只做卡片与画布的分离 |

**控件 32 不是 48。** 48 是 Material 的触摸目标，不是桌面控件高度。此前为了
绕开 `DropdownButton` 的 `kMinInteractiveDimension` 断言把全站控件抬到 48，
结果是每个工具栏、筛选行和对话框都比内容高出一截，按钮在 13–14px 文字旁边
显得又粗又空。下拉框已改为自绘列表（`HaloDropdown`），不再受该断言约束，
所以控件回到 Fluent 的 32。

**弹出菜单 32，且不取整到 56。** `showHaloMenu`
（`apps/flutter/lib/src/ui/widgets.dart`）是唯一的弹出菜单实现，右键菜单、
工具栏「更多」、以及任何二级选择都用它，不要再用 `showMenu` /
`PopupMenuButton`。后者带来三个参数改不掉的问题：`PopupMenuItem.height` 默认
48（一行 18px 文字配 30px 空白，十项菜单高 500px）；路由内部用
`IntrinsicWidth(stepWidth: 56)` 把宽度向上取整，最宽可多出 55px 死区——这
两条合起来就是「又大又空」。第三个问题是 `useMaterial3` 下菜单读
`labelTextStyle` 而非 `textStyle`，主题里写 12px 会被静默忽略，于是全站菜单
按 13px/600 渲染，比打开它的按钮还重一档。

菜单与下拉是同一个控件的两种状态，所以两者共用同一组数字：行高 32、横向
内缩 10、圆角 4、边框与文字样式一致。

**快捷键单独成列，不要拼进标签。** 写成 `Text('设为当前节点\tEnter')` 时
制表符被画成句中一段空格，快捷键落在离标签忽远忽近的位置，还会被读成动作
名称的一部分。改用 `HaloMenuItem.shortcut`：右对齐固定 56px 列，全列共用
一条右边缘；只有当菜单里存在快捷键时才预留这一列。

**图标按钮 36 / 28。** 16px 字形放 48px 盒子里，一行五个图标就吃掉 240px，
还把规则行撑到 54px 高。图标是鼠标目标，不是手指目标。

## 3. 字体

Segoe UI + `Microsoft YaHei UI` 回退(中文必需;Segoe UI 无中文字形)。

| 层级 | 字号 | 字重 |
| --- | --- | --- |
| 页面标题 | 18 | 600 |
| 卡片标题 | 14 | 600 |
| 正文 / 按钮 | 13 | 400 / 600 |
| 说明 / 标签 | 11.5 | 400 |
| 数字(延迟、速率、出口 IP) | 18–20 | 600,Consolas + 等宽数字 |

**这是 1180x760@200% 下的桌面密度，不是手机密度。** 上一轮为了修「正文发虚」
把正文提到 14、卡片标题提到 16、页面标题提到 20，同时把控件抬到 48；在 200%
缩放下卡片标题和页面标题几乎一样大，一层工具栏就顶到视口外，正文反而因为
行高变高显得更空。现在每一级只差一档：18 / 14 / 13 / 11.5。

数据表（节点、连接、日志）用 11.5，比正文小半档：一屏要放 15 行以上，
行高 22–38。

**数字比标签大，不反之。** 总览是为读数而打开的页面，但此前同一页上出现了
10.5 / 11 / 11.5 / 12 / 12.5 / 13 / 13.5 / 14 八种字号且没有规则，结果「0 B/s」
比解释它的说明还轻，整页没有一个东西读起来像答案。现在所有度量值走
`haloMetricStyle(context, size: 18–20)`（Consolas + `FontFeature.tabularFigures`，
数字换宽度时同一行不会跳动），标签一律 11.5。迟到的特例只有一个：
「当前节点」的节点名用 `titleSmall`(13/600)，因为它是标识而不是数值。

## 4. 动效

| 场景 | 时长 | 曲线 |
| --- | --- | --- |
| 悬停、按下、选中迁移 | 120ms | `easeOut` |
| 开关滑块、较大位移 | 220ms | `easeOutCubic` |

### 4.1 提示条停留时长

所有浮动提示走 `showHaloToast`（`apps/flutter/lib/src/ui/widgets.dart`），时长由消息
本身决定，调用点不自己挑数字：

| 类型 | 时长 | 用在哪 |
| --- | --- | --- |
| 确认 | 2s | 结果已在界面上可见，提示只是复述（已复制链接、开关已切换） |
| 告知 | 3s | 一句话说明刚发生了什么 |
| 详情 | 5s | 带数字、路径或失败原因的句子，需要再看一眼 |

**上限 5s。** 此前大部分调用点不传时长，吃 Flutter 的默认 4s，订阅页两处是 8s、
连接页是 2s——同一个界面里三种答案，而 8s 的提示在用户已经忘记触发动作之后还盖在
页面上。需要比 5s 更久才能读完的内容应当放进对话框，而不是一条盖住页面的条。

**带按钮的提示也必须自己消失。** Flutter 的 `SnackBar` 在 `action != null` 时默认
`persist = true`，于是「查看」「撤销」这类提示会一直停在屏幕上，直到用户手动关掉。
`showHaloToast` 显式传 `persist: false`：按钮在提示停留的这几秒里可用，时间到后整条
一起收走，需要保留的操作应当放进对话框或行内按钮。

## 5. 文案语域

界面文字描述**产品做了什么**,不描述作者**怎么看待它**。一句话对不对,看主语:
"级别越低,写入的内容越多"讲的是设置的行为;"级别越低越啰嗦"讲的是写作者的感受。

| 避免 | 改用 | 原因 |
| --- | --- | --- |
| 级别越低越啰嗦 | 级别越低,写入的内容越多 | 「啰嗦」是主观评价 |
| 内网服务,别绕代理 | 内网服务,不经代理 | 口语指令 |
| 内核不会自己回来 | 已停止的内核在下次启动后仍保持停止 | 拟人 |
| 自动恢复代理(不弹窗口) | 自动启动并恢复代理,不显示窗口 | 括号里的口语补丁 |
| 避免节点争用带宽 | 避免节点同时占用带宽 | 用词不稳定 |
| 可直接粘贴到 issue | 适用于提交问题报告 | 开发腔 |

不出现语气助词、比喻、拟人、网络用语,以及「您只需 / 轻松 / 一键 / 搞定」这类营销词。
**防回归**见 `apps/flutter/test/page_rhythm_test.dart` 的
`user-facing copy avoids spoken-register filler`:它遍历全部页面渲染出的文字,
断言不含黑名单词。黑名单只收真正回归过的短语,是下限而不是文风手册。

## 6. 组件规则

- **SectionCard** — 阴影在外层 `DecoratedBox`,表面在内层 `Material`。中间
  不能放带底色的 `DecoratedBox`,否则 `ListTile` 的墨水效果被吞掉(Flutter 会
  直接断言失败)。
- **空状态的三种用途不要混** — 页面级空状态(节点页、订阅页、规则页)用整版
  版式;卡片内部用 `compact: true`(见上文)。同一个「没有内容」在两处出现时,
  优先级低的那处只留一句话。
- **配对行的卡片不「撑满」内部** — `IntrinsicHeight` 只把两张卡的**外框**拉到同高,
  卡内内容仍从顶部按自己的间距排列。试过让正文 `Expanded` 撑满、再用
  `spaceBetween` 把最后一行压到底边:短卡中间被撑出一条大缝,比底部留白更像坏了;
  而且 `Spacer` 这类 flex 子节点在 `IntrinsicHeight` 的无限高度测量下会直接断言。
  留白放在卡片下沿可以接受,放在段落之间不行。
- **HaloSwitch / HaloSwitchTile** — Fluent 几何:40×20 轨道、12px 滑块、开启
  为强调色、关闭为透明加 1px 描边。`onChanged` 为 null 即为禁用,整行点击在
  禁用时同时失效。
- **HaloSelector** — 选择条,选中段落用 card 表面 + 描边 + 阴影浮起。默认按内容或
  固定宽度使用,不要拉满整张卡片:三段两字标签铺 700px 会变成一条没人认得的跑道。
- **HaloFilterChip** — 分组/来源筛选用的胶囊。节点页与订阅页共用同一个组件,
  不要再各画一套(此前一边是自绘 pill、一边是 Material `ChoiceChip`,同一个控件在
  两页上高度和圆角都不一样)。放它的容器必须能换行,理由见 7.4。
- **InfoRow** — 标签列固定 104px。此前用 flex 3/5,在宽窗口下短标签与值之间
  会留出约 200px 的空洞;132px 又在每一行多付 28px。表单页用它(标签长);
  总览的短标签用 `_Fact`,标签列 48/64px,否则每个值都被推到卡片左边 116px 之外。
- **卡片标题与卡片正文必须同一条左边缘** — `HaloSwitchTile` 曾带 4px 横向内边距,
  于是「设置 Windows 系统代理」比它上面的「系统代理」标题右移 4px。看得见却说不出
  的错位大多来自这种「组件自带一点内边距」。
- **InfoRow 的值不能再加 `maxLines`** — `SelectableText` 会把 `maxLines` 当成
  **预留高度**:`maxLines: 2` 时一行内容也占两行(实测 38px 对 19px)。一叠
  InfoRow 因此每行 44px,一张四行卡白付 76px。需要限制行数就用 `Text`,
  需要可选中就不要设 `maxLines`。
- **空状态** — 36px 三级色图标 + 13.5px 标题 + 11.5px 说明 + 可选主按钮,居中。
  卡片内部用 `compact: true`(28px 图标),否则一张 200px 高的卡要付 300px 的版式。
- **HaloField** — 标签固定在控件**上方**。不要再复用 Material 的
  `InputDecoration.labelText`:它把标签浮到描边线上,和本规范的 Fluent 表单不是
  一套。说明文字放控件下方,11.5px 三级色。
- **表单行 / 设置行** — 标签块固定 200px,控件紧跟其后;说明文字放控件**下方**
  并占满整行宽度。此前说明挤在 240px 的标签列里,四句话折成四行,而控件右侧
  250px 空着——一行字撑起整张卡的高度。表单页整体限宽 760px 居中
  (`HaloPageScaffold.maxContentWidth`),否则标签与控件之间会隔出 800px 的空洞。
- **开关行** — 开关放在行尾(WinUI 的设置页惯例),文字在左;卡片限宽 760 已经把
  这段间距控制在 `240px` 以内。开关只表达开/关,不要再在它后面加一个「开 / 关」
  文字,同一个事实出现两次。
- **间距只有四档** — `cardGap` 12(卡与卡)、`blockGap` 8(卡内两块)、
  `lineGap` 4(同一块的两行)、`hairGap` 2(标签与其数字)。**全站所有页面**都用这
  四档:设置、订阅、规则、节点、连接、测试页原先各自用 8 分隔卡片,与总览的 12
  差一档,同一个「两张卡之间」在两页上是两个尺寸。**不要写裸数字**:
  总览页此前同时用了 8、10、6、4、2 和 0,于是「卡片之间的空隙、页头与第一张卡、
  一列的最后一张卡与下面的整宽卡」是三份不同的答案——这就是「间距不均匀」。
  卡与卡之间必须比卡内更松(12 > 8),否则一列卡片会读成一整张表格。
- **两列表格(总览)** — **按行配对**,同一行的两张卡共享一个高度(`IntrinsicHeight`
  + `CrossAxisAlignment.stretch`)。此前的独立双列不需要内在高度,但每列各自结束在
  自己内容的末尾:左列比右列早结束约 80px,下面的整宽卡就在那个空洞之后才开始。
  配对的前提是**卡里不能有 `LayoutBuilder`**——它不报告内在高度;明细列表因此改成
  由调用方传列数(`_Facts(columns: ...)`),不再自己测量宽度。
- **配对按「同一条问题 + 相近高度」** — 当前节点 | 实时流量(出口是谁、多快)、
  代理内核 | 出口信息(通不通、从哪出)、系统代理 | TUN(两个接管开关)。
  `HomeCard` 的枚举顺序是偏好存储用的,不是版面顺序;两者不必一致。
- **系统代理与 TUN 是一个选择，不是两个开关** — 同一时刻只有一个内核在跑，两者
  都指向本机 mixed 入站的同一个端口。因此开启任一个都会关闭另一个（宿主强制，
  见 `tunTakesOverSystemProxy` / `leaveTunForProxyMode`）。界面必须提前说明，
  不能等用户点完再从日志里发现：
  - TUN 接管时，系统代理开关**保持可用**，副标题写「开启将关闭 TUN，切回普通
    代理」。打开它正是用户回到普通代理的入口；置灰会让 TUN 成为这张卡片上唯一
    可达的状态。卡片仍然只报告**本项**的状态（已开启/已关闭），不借用 TUN 的状态。
  - TUN 未开启而系统代理已开启时，TUN 开关的副标题写「启用后将关闭系统代理，
    由 TUN 接管全部流量」。一个控件伸手去关另一张卡片里的开关，必须在点之前说。
  - 托盘菜单同一道理：「系统代理」在 TUN 下保持可点，标签写明「（点击关闭 TUN）」。
    **不要**置灰，也不要让它静默停掉 TUN——前者让用户回不去，后者让一个标签写着
    「系统代理」的菜单项触发大动作却毫无预告。
  - 代理内核卡片在 TUN 下显示 `tunPid`（标注「（TUN）」），不能显示 `—`：
    `corePid` 在 TUN 下**故意**为 0（内核是服务的子进程），而「—」在「运行中」
    旁边会被读成「没有进程」。
- **卡片里的数字用 `haloMetricStyle`** — 总览的延迟/速率/出口 IP 用 18–20,节点表
  的延迟、速度、端口连通三列用 11.5,但**同一个函数**:等宽数字(`tabularFigures`)
  保证换行不跳动,并且表格和仪表盘对「这是一个数值」给出同一种表达。
- **状态胶囊只有 `StatusChip`** — 规则行动作(代理/直连)曾是手画的 `Container`:
  自己的圆角(10 而不是 4+4)、自己的透明度(0.14)和自己的字号,于是同一种「状态」
  在这页和别的页长得不一样。现在一律 `StatusChip(label:, color:)`。
- **一个事实只出现一次** — 节点总数已经在分组 chip 和表格底栏里,页头副标题就只写
  「正在使用哪个节点」;连接数为 0 时表格空状态已经说了,页头就写「实时连接列表」。
- **空状态不要用一句话顶替版面** — 总览的 TUN 卡在空闲时曾同时写「启用时会弹出系统
  授权窗口」和「启用时将请求一次管理员授权…」,同一个事实两遍,卡片因此比内容高。
  开关行只写开关无法表达的东西(缺少组件、等待授权),说明文字只留一条。
- **弹出菜单只有 `showHaloMenu`** — 右键菜单、工具栏「更多」和二级选择都用它，
  不要用 `showMenu` / `PopupMenuButton`。理由见 §2：48px 行高、56px 宽度取整、
  主题文字样式被静默忽略，这三条用参数都改不掉。菜单面板必须包一层
  `Material`（`type: transparency`），否则文字会被画上黄色下划线——widget test
  不报错，只有真实窗口能看出来。
- **表单标签在控件上方，不要在描边上** — 用 `HaloField`，不要用
  `InputDecoration` 的 `labelText`。后者把标签浮到描边线上，和本规范的 Fluent
  表单不是一套；节点详情与编辑订阅两个对话框此前就是这样，现已改为
  `HaloField` + `HaloDropdown`。
- **`Sparkline` 的「等待采样…」必须可读** — 它此前取 `grid`(基线描边色),画在
  卡片上等于隐形;判定条件也从 `samples.isEmpty` 改成 `length < 2`,因为第一次
  轮询只建立基线、没有画出任何曲线。

## 7. 导航与操作流

导航顺序就是操作顺序,不做分组标题:第一项是「我现在好不好」,第二、三项是
唯一的两步前置动作(导入订阅 → 启用节点),其余是配置与诊断。

| 序号 | 页面 | 职责 |
| --- | --- | --- |
| 1 | 总览 | 内核启停、系统代理、TUN、分流模式、下一步指引 |
| 2 | 订阅 | 导入订阅与分享链接 |
| 3 | 节点 | 节点列表、延迟列与测速、启用节点、批量整理 |
| 4 | 规则 | 用户规则:哪些流量直连、哪些走代理 |
| 5 | 测试 | 解锁检测:13 个流媒体 / AI 服务的判定 |
| 6 | 连接 | 实时连接列表、搜索、单条与全部关闭 |
| 7 | 日志 | 脱敏日志流 |
| 8 | 设置 | 外观、运行方式、本地数据 |

**测速不是独立页面。** 测速结果就是节点列表的「延迟」列,可按延迟排序;这是
v2rayN 的做法 —— 测速与选点是同一件事,拆成两页会让用户离开他正在挑选的列表。
「测试」(解锁检测)与「连接」(实时连接)是另外两件事:前者回答"当前出口解锁了
哪些服务",是 13 个独立判定;后者是流量视图,按 1.5 秒刷新。把它们塞进节点表
只会让那一页变成三个不相关功能的容器。同理,「工具与设置」这类分组标题也被
去掉:八个页面的层级差异用位置表达即可,多一层标题只是噪音。

### 7.1 一条常驻状态栏

窗口底部固定一条 32px 状态栏,从左到右按数据流顺序回答三个问题:

| 段 | 回答 |
| --- | --- |
| 内核 | 我能不能用 |
| 节点 | 出口是谁 |
| 系统代理 / TUN | 流量有没有被接管 |
| 分流 | 走什么规则 |

右端是**唯一的下一步指引**或「已就绪」。窄窗口下按 分流 → TUN → 系统代理 的
顺序丢弃分段,内核与节点在任何宽度都保留(它们解释"为什么不通")。

`AppController.nextStep` 是这条指引的唯一来源,总览卡与状态栏都读它,不各自
判断。规则按顺序短路:数据库 → 后台连接 → 有无节点 → 有无当前节点 → 内核是否
运行 → 代理/TUN 是否接管。

### 7.2 选中 ≠ 启用

点击行只表示"选中"(批量整理用);启用是页头的「启用所选节点」、右键菜单的
「设为当前节点」或 Enter。已生效的行带左侧 3px 强调条 +「使用中」徽标。这样勾选
多行做批量重命名时不会误触发配置切换。

行尾不再单设「启用 / 当前」一列：同一个动作在页头、右键菜单和 Enter 上已经有了三处
入口,第四处排成常驻一列既让表格窄 64px,又让"当前"与「使用中」徽标、强调条重复
表达同一件事。**一个事实只在版面上出现一次**。同理,表格底栏只保留筛选后的计数与
快捷键提示——「当前节点」常驻在底部状态栏,筛选栏也不再把总数念一遍。

### 7.3 延迟配色

只用一套语义,凡是显示延迟的地方一律复用 `latencyColor`:

| 范围 | 颜色 | 含义 |
| --- | --- | --- |
| ≤ 200ms | 绿 | 可用 |
| ≤ 600ms | 琥珀 | 慢 |
| > 600ms | 红 | 不可用 |
| 无结果 / 失败 | 三级灰 / 红 | 未测 / 不通 |

测速开始前先清空该批节点的旧结果,避免陈旧数字被读成新结果。

### 7.4 节点页

![节点页：延迟列、使用中徽标](images/ui-nodes.png)

订阅源筛选条（分组 chip）**必须换行，不能用横向滚动列表**。此前它是
`ListView(scrollDirection: horizontal)`：一行放不下 9–11 个订阅源，多出来的
被排到视口右侧之外，而桌面端**鼠标滚轮只滚垂直方向**，Flutter 的
`dragDevices` 又排除了鼠标，于是在界面上根本点不到——不是"看不全"，是
"选不了"。

现在用 `Wrap` + 最多三行的 `ConstrainedBox`：三行以内全部可见；订阅源多到
超过三行时改为纵向滚动（滚轮可用），而不是无限增高把表格挤出窗口。
表格的「分组」列宽也从 84 提到 120，`chengaop…` 这种长名字至少露出可辨认的
前缀，完整值仍由 tooltip 承载。

「清理无效」只作用于**当前筛选/搜索后的显示集合**，判定标准是“至少一项测速或
连通性检查失败，且没有任何成功结果”。未测、已取消、不适用与 UDP 未确认都不算
无效；慢节点也不算。移除前弹出数量确认，移除后可撤销。测速进行中禁用该动作，
避免删除正在写入结果的行。

**表头：排序区与拖动条之间不能有空白。** 单元格自带的 8px 横向内边距必须在
`InkWell` **里面**：放在外面时，每一列表头的最后 8px 既不排序、也拖不动，而相邻
两列的这两段又贴在一起，于是「点击」与「拖动」之间是一条 16px 的无声带——鼠标
停在那里是指针而不是调整列宽的光标，点下去也不排序。节点页十列就是 80px 的
这种区域。现在一个列只有两种落点：7px 拖动条调整列宽，其余部分（含内边距）排序。
点击区与拖动条共享同一条边界，不需要靠猜。

**选中发生在按下的那一刻，不能等双击窗口。** 行既认单击（选中）又认双击（打开
详情）。两者写在同一个 `GestureDetector` 上时，双击识别器会在第一次抬手后
`gestureArena.hold()` 住整个手势场 300ms（`kDoubleTapTimeout`），等第二次点击；
那次 hold 同时扣住了兄弟 `onTap`，于是每一次单击都要等 1/3 秒才出高亮，连点几行
就像表格没反应。现在单击走 `Listener.onPointerDown`（只认左键），按下即选中；双击
仍由 `GestureDetector.onDoubleTap` 识别，详情照开。这也正是 Explorer 的语义：
按下即选中，双击只是附加动作。顺带一条：Shift 范围与当前选中完全相同（双击的第二
下、重复点同一端）时不再 `setState`，否则只是白重绘整张表。

### 7.5 通知通道

控制器不再用单一 `revision` 驱动整棵树,而是五条窄通道:
`runtimeRevision`(后台快照)、`proxyRevision`(仅 Windows 系统代理那一项)、
`catalogRevision`(节点/订阅表)、`connectionRevision`(管道)、
`errorRevision`(底部错误条)。页面宿主 `_PageHost` 只为**当前页**订阅快照/表/管道
三条,并且用工厂函数而不是传入现成 widget —— 传入同一个 widget 实例会让 Flutter
跳过重建,这正是"通道改了但界面不刷新"的成因。

**一次变化只该重绘它真正影响的范围。** 切换系统代理只改一个布尔值,却曾经过粗通道
惊动了侧边栏、状态栏和整页(含节点表)。现在快照进入控制器时先做差异判断
(`adoptSnapshot`):若除 `systemProxy` 外整份快照完全相同,就只发 `proxyRevision`,
总览页的代理卡片与 TUN 卡片各自订阅它,页面本身不重建。

两个实现细节值得记住,它们都真的踩过:

- **不能手写字段比较清单。** 第一版只比了 8 个字段,漏掉 `speedTestRunning` 等,
  于是批量测速期间节点页被「窄通道」吞掉更新、表格卡在测试中。现在把 `toJson()`
  去掉 `systemProxy` 后整体序列化比较,新增字段自动覆盖。
- **`stateVersion` / `updatedAtMs` 不参与比较。** 宿主每次写快照都会推进这两个值,
  比了它们,窄通道就永远不会触发。时间戳等下一次真正需要重绘的变化再追上。

节点/订阅读取带缓存,由 `invalidateCatalogCache()` 失效。此前每次 build 都做
一次 `SELECT *` 加逐行 JSON 解码,是列表滚动发涩的主因。

## 8. 深色标题栏

Windows 标题栏颜色由 runner 决定,而 runner 只读**系统**主题。用户在设置里选
「深色」而系统是浅色时,会出现深色界面配白色标题栏。

因此 `flutter_window.cpp` 注册了 `clash_halo/theme` 方法通道,Dart 侧在主题
变化与 `didChangePlatformBrightness` 时调用 `setDark`,由
`DwmSetWindowAttribute(DWMWA_USE_IMMERSIVE_DARK_MODE)` 设置标题栏。通道缺失
(例如 widget 测试、旧 runner)时调用失败被吞掉,不影响启动。

## 品牌图标

三处界面必须共用同一套图案：窗口图标、任务栏/托盘图标、侧栏 logo。
历史上它们各画各的（窗口用 Flutter 默认 logo、侧栏用紫色闪电、托盘用代码画的圆点），
所以现在统一由 `tools/build-icons.py` 从一个源生成，改图标只改这一个脚本。

### 图案与来源

猫头形状取自 `clash-verge-rev`（GPL-3.0）的 `ClashVergeCat.svg`，本项目按
GPL-3.0-or-later 发布（见 方案.md），许可兼容；**只替换配色，不重画造型**：

| 元素 | 颜色 | 说明 |
| --- | --- | --- |
| 底盘 | `#6B4FBB`（HaloColors.primary），**纯色实心圆** | 与侧栏选中色一致 |
| 猫脸 | 纯白 | 主体剪影 |
| 眼孔 / 鼻 | `#3B2A6B` | 源图里是镂空透出背景色，这里直接填深紫以保证小尺寸对比度 |

早期版本在圆内加过青色光环与深紫外圈，实机看是两条多余的同心底纹，
在小尺寸下更像“另一个 logo”，已去掉；现在只有实心紫底 + 白猫。

### 托盘三态

托盘图标随代理状态换色，与 Clash Verge Rev 的做法一致（它按 common/sysproxy/tun
分发三套图标），本项目用主题色：

| 状态 | 底色 | 判定 |
| --- | --- | --- |
| `idle` | `#6B4FBB` 品牌紫（原色） | 系统代理关闭且 TUN 未启用 |
| `active` | `#3E9A3E` 绿 | 系统代理已开启 |
| `tun` | `#0F6CBD` 蓝 | TUN 已启用 |

优先级：TUN > active > idle（TUN 与系统代理可同时开启，TUN 是更强的“流量去向”声明）。

**内核在跑不算“已接管流量”。** 早期版本把 `CoreState == running` 也算作 `active`，
结果是界面一启动、内核被拉起，图标立刻变绿——而系统代理根本没开，机器上的流量也没
走这个应用。图标只回答一个问题（“这台机器的流量是不是正在被代理”），所以只有
系统代理或 TUN 这两个**改了路由**的开关才换色；内核自己运行着仍然是原色紫。

气泡提示与图标颜色必须一致，由 `trayTooltip` 一并给出：

| 图标 | 提示 |
| --- | --- |
| 紫 | `代理已停止` / `内核运行中，系统代理未开启` / `内核异常：…` |
| 绿 | `代理运行中：{节点}` / `系统代理已开但内核异常：…` |
| 蓝 | `TUN 已接管全部流量[：{节点}]` / `TUN 已开但内核异常：…` |

“开关开着但内核死了”是最糟的状态，所以它保留开关对应的颜色，同时在提示里点名异常，
而不是被一句“运行中”盖住。

两个实现要点（都踩过）：

- `systray.SetIcon` 在 Windows 上要的是**真正的 .ico 字节**，不是 PNG。它把字节写到
  临时文件再 `LoadImage(..., IMAGE_ICON, LR_LOADFROMFILE)`，传 PNG 会失败并在日志里
  留下 `Unable to set icon`——此时托盘仍是空白默认图标。三态图标因此都以 ICO 形式
  烘焙进 `trayicon_gen.go`，每个含 16/24/32/48/64/256 六档。
- 图标在 `systray.Run` 的 `onReady` **内**设置，且只在变体真正切换时才调用 `SetIcon`
  （它每次都会重写临时文件并重新加载位图）。宿主会记录
  `托盘图标已应用（idle）` 与后续的 `托盘状态=…`，没有 `Unable to set icon` 即为成功。

### 生成与产物

```powershell
py -3 tools/build-icons.py
```

一次生成：

- `apps/flutter/windows/runner/resources/app_icon.ico` — 16/20/24/32/40/48/64/128/256 九种尺寸，
  每档独立栅格化（不是把 256 缩放下来），这是小尺寸清晰的关键；
- `apps/flutter/windows/runner/resources/tray-icon{,-active,-tun}.ico` — 三态参考图
  （宿主用的是烘焙进二进制的同一批字节，这些文件仅用于查看）；
- `native/windows/cmd/halo-host/trayicon_gen.go` — 三态托盘 ICO（各 6 档尺寸）烘焙进
  宿主二进制（宿主单文件分发，不能依赖旁边的图片；缺图就等于没有托盘图标）；
- `apps/flutter/assets/brand/brand_cat.png` — 侧栏 logo（96px，供 24 逻辑像素在 4x 屏使用）；
- Android 五档 `ic_launcher.png`；`docs/images/brand-cat.png` 预览
  （预览图同样不入库，由本脚本生成）。

### 修改图标时的注意事项

- 不要引入 SVG 渲染依赖：脚本自行解析源 SVG 的 path（只用到 `M/C/Z`）并用 Pillow 填充。
- 源 SVG 是**复合路径**：外轮廓 + 三个反形状（两眼一鼻）。Pillow 没有 even-odd 填充规则，
  因此脚本先填最大子路径作为脸，再单独填三个孔；直接依次 `polygon()` 会把孔盖掉。
- 16px 下不画胡须与高光（脚本按尺寸阈值跳过），否则会糊成一团。
